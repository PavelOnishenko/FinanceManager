# Приёмка 3.1: запуск Wrangler из установщика

Проверяем служебный код, а не готовый мастер установки. Он запускает команды Wrangler, передаёт данные,
получает ответ и обрабатывает ошибки. Аккаунт Cloudflare и токен Telegram не нужны. Все проверки выполняются без сети.
Не запускайте login, deploy или удалённые команды D1 для этой приёмки.

## Что подготовить

На компьютере разработчика с Windows откройте PowerShell в папке проекта на ветке `feat/installer-task3-1-wrangler-runner`.
Нужны установленные зависимости проекта, как при проверке Task 2, и уже проверенный распакованный пакет Task 2.
Его не нужно пересобирать: из него используем только Node и Wrangler. Новая функция запуска берётся из исходников текущей ветки.
Чистая Windows без инструментов разработчика повторно не требуется: состав пакета не менялся.

## 1. Автоматические проверки

Выполните:

```powershell
$ErrorActionPreference = 'Stop'
$env:NPM_CONFIG_UPDATE_NOTIFIER = 'false'
npm.cmd run installer:check
if ($LASTEXITCODE -ne 0) { throw 'Проверка типов не прошла' }
npm.cmd run installer:test
if ($LASTEXITCODE -ne 0) { throw 'Тесты установщика не прошли' }
```

Ожидается: обе команды завершаются с кодом 0, все тесты проходят без пропусков.
Кроме существующих тестов упаковки выполняются проверки новой функции на настоящих дочерних процессах с тестовыми скриптами:

- Аргументы с пробелами и специальными символами передаются как значения; используются заданные рабочая папка и файлы.
- Посторонние переменные аккаунта, токена, endpoint и `NODE_OPTIONS` не наследуются. Proxy и сертификаты сохраняются.
- Токен передаётся через stdin; в ошибках и предупреждениях вместо известных секретов выводится `[скрыто]`.
- Код ошибки сохраняется. Timeout и отмена после запуска сообщают, что изменение могло произойти, и не повторяют команду.
- Отмена до вызова не запускает процесс. Неверный JSON отклоняется без раскрытия исходного ответа.

Это выдуманные токены и операции над временными файлами. Настоящие настройки Cloudflare не меняются.

## 2. Запуск настоящего Wrangler из пакета

Укажите папку, внутри которой находятся `runtime` и `wrangler`, например папку `package` из результата Task 2.
Замените путь ниже своим, сохранив кавычки:

```powershell
npm.cmd run installer:verify-wrangler -- 'K:\Programming\work\releases\family-finance-1-windows-x64\package'
if ($LASTEXITCODE -ne 0) { throw 'Запуск Wrangler из пакета не прошёл' }
```

Ожидаются код 0 и строки:

```text
Wrangler 4.133.0: запуск из пакета работает.
Справка D1 получена. Вход, миграции и обращения к Cloudflare не выполнялись.
```

Команда создаёт отдельную временную папку с пробелами в пути и тестовыми настройками,
запускает bundled Node и `wrangler-dist/cli.js` с `--version`, затем `d1 migrations apply --help` и удаляет временную папку.
Запуск CLI напрямую позволяет завершать сам Wrangler при timeout, не оставляя отдельный процесс его Node-обёртки.

## Результат

3.1 можно принять, когда оба шага прошли на Windows. Сообщите commit и результат каждого шага;
если проверка не прошла — команду и текст ошибки. Секреты присылать не нужно.
Автоматические проверки и версия/справка настоящего Wrangler уже проверены в Linux с Node 24.19.0.
Windows Node 24.13.0 из пакета должен быть проверен владельцем по этой инструкции.
Права доступа, вход в Cloudflare и ответы удалённых операций проверяются в следующих подзадачах.
