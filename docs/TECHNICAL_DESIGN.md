# Техническое описание MVP

## Стек

- TypeScript со строгой проверкой типов.
- Cloudflare Worker как HTTPS webhook Telegram.
- grammY как тонкий слой над Telegram Bot API.
- Cloudflare D1 только для постоянных семейных данных.
- Wrangler для локальной разработки, миграций и развёртывания.
- Встроенный test runner Node.js для тестов.

D1 API изолирован небольшим типизированным adapter: repository использует только локальные интерфейсы `SqlDatabase`, `SqlSession` и `SqlQuery`. Adapter преобразует `first/all/run` и D1 sessions в стабильные операции `one/many/execute` и `withPrimarySession`; ORM и универсальный query builder не используются.

Доменная логика не зависит от Telegram или D1. Обработчики преобразуют входящее сообщение в команду, вызывают доменную операцию и формируют русский ответ.

## Модули

```text
src/
  config/       категории и постоянные настройки
  domain/       разбор ввода, правила расходов и статистики
  application/  пользовательские сценарии
  storage/      запросы D1
  telegram/     команды, кнопки и webhook
  index.ts      входная точка Worker
migrations/     последовательные миграции D1
tests/          тесты доменных правил
```

Папки `application`, `storage` и `telegram` добавляются вместе с соответствующими сценариями, а не создаются заранее пустыми.

## Модель данных

- `members`: вручную заданный Telegram ID, отображаемое имя и флаг доступа.
- `categories`: русское название, порядок показа и активность.
- `expenses`: уникальный ключ пользовательского действия, сумма в целых RSD, категория, локальная дата расхода, комментарий и автор.

Дата расхода хранится как локальная календарная дата `YYYY-MM-DD`. Момент создания и изменения хранится в UTC. Текущая дата определяется в часовом поясе `Europe/Belgrade`.

## Сценарии

### Добавление

Сообщение только с суммой не создаёт черновик. Бот помещает сумму и Telegram update ID исходного сообщения в `callback_data` кнопок категорий. Нажатие категории приносит все необходимые данные и создаёт расход атомарно. Из исходного update ID строится `source_action_key`, уникальный для расхода. Все кнопки одного ввода используют тот же ключ, поэтому повторная доставка сообщения и двойной тап не создают дубликат. Сообщение с суммой, категорией и необязательным комментарием создаёт расход сразу по тому же правилу.

### История и редактирование

Показываются 10 последних расходов. ID записи передаётся кнопками через `callback_data`. Для новой суммы, даты или комментария бот отправляет стандартный Telegram `ForceReply` с ID операции в тексте. Ответ пользователя содержит `reply_to_message`, поэтому Worker восстанавливает ID и поле без серверного состояния. Категория меняется кнопкой сразу. Обновляется сама запись и `updated_at`; отдельная история не создаётся. Удаление требует подтверждения.

### Статистика

По умолчанию вычисляется предыдущий календарный месяц. Запрос группирует расходы по активным и неактивным категориям, чтобы старые записи не исчезали после отключения категории. Границы произвольного периода включаются полностью.

### Доступ

Семейные Telegram ID однократно добавляются напрямую в D1 после развёртывания и не хранятся в Git. Пользователь с `enabled = 1` имеет полный доступ к общим расходам и статистике. Неизвестному или отключённому пользователю бот отвечает отказом. Интерфейса управления участниками нет; редкие изменения выполняются вручную через SQL. Для отзыва доступа используется `enabled = 0`, а не удаление строки, чтобы сохранить автора старых расходов.

## Безопасность

- Токен Telegram и webhook secret хранятся только в Cloudflare Secrets.
- Каждый webhook проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`.
- Все операции проверяют наличие участника с `enabled = 1`.
- SQL использует связанные параметры.
- Секреты, `.dev.vars` и локальные данные Wrangler исключены из Git.
- Текстовое редактирование принимается только как ответ на prompt, отправленный самим ботом.

## Границы первого релиза

Одна семья, одна валюта RSD, русский интерфейс и одна развёрнутая копия бота. Доходы, EUR, конвертация, графики, чеки, банковские интеграции и история редактирования отсутствуют.

Названия и алиасы категорий могут содержать только буквы, цифры и обычные пробелы. Нарушение этого контракта останавливает приложение при загрузке конфигурации; экранирование специальных символов не выполняется.

## Правило тестов

Каждое созданное тестом значение, которое проверяется или определяет проверяемое поведение, задаётся непосредственно внутри соответствующего теста. Вспомогательные функции могут содержать только несущественные технические значения; ожидаемые данные нельзя скрывать в значениях по умолчанию. Канонические данные приложения из production-миграций или конфигурации являются частью проверяемой системы и не должны повторно создаваться внутри теста.
