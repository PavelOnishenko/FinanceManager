# Ближайшая работа: установить бота одному другу

Цель — сопровождаемая установка за 3–5 рабочих дней. Разработчик выполняет действия на Windows x64 друга через
AnyDesk или TeamViewer, друг подтверждает аккаунты и настройки. Установку и обновления выполняем вручную по инструкции.

## Текущее состояние

Бот поддерживает общие расходы, редактирование и удаление, категории, подпись валюты, часовой пояс,
историю за период с пагинацией и статистику. Категории и настройки хранятся в D1; защита от дублей использует `source_action_key`.
Каждой семье нужны собственные Telegram-бот, Cloudflare Worker и D1: все участники одной базы видят её общие расходы.

Task 1 завершена: основные операции провайдеров проверены вручную на Windows и в отдельном аккаунте.
Task 2 завершена: ZIP со встроенными Node/Wrangler, Worker и миграциями собран и проверен на Windows x64.
Перед передачей другу нужно привести состав ZIP к описанному в инструкции сборки, проверить готовый архив
на компьютере разработчика и отрепетировать полный проход ручной установки.

## Порядок работы

1. [Task 3](deployment/INSTALLER_TASK_3.md): подготовить инструкцию оператора и только необходимые короткие команды.
   Бюджет — день 1. Подготовить ZIP только с необходимыми файлами, отдельную конфигурацию и проверенные операции Task 1.
2. Task 4: пройти инструкцию с тестовым ботом в отдельном аккаунте из итогового ZIP, включая продолжение после закрытия
   терминала и redeploy с тестовыми расходами. Бюджет — день 2.
3. Task 5: установить другу, проверить двух участников, отказ постороннему и работу при выключенном компьютере.
   Оставить владельцу конфигурацию, сведения об экземпляре и памятку. Цель — день 3; дни 4–5 для блокеров и повторных проверок.

Точные границы, критерии готовности, обслуживание и обновления:
[план пилота](deployment/INDEPENDENT_FAMILY_DEPLOYMENT_PLAN.md).
Причины выбранного объёма: [принципы пилота](deployment/PILOT_APPROACH.md).

Не добавлять новые финансовые функции в этот срок. Обновления проводим вручную;
небольшие вспомогательные команды выбираем по времени и ошибкам реальных сеансов.

## Проверки

Следовать `AGENTS.md`. Для документации проверять diff и ссылки; тесты приложения не запускать.
Для кода проверять затронутое поведение и давать короткий способ ручной проверки с ожидаемым результатом.
Локальный тест не подтверждает удалённое развёртывание или Telegram. Удалённые операции выполняются только в согласованном сеансе.

[Сборка ZIP](deployment/FAMILY_RELEASE_BUILD.md) и [приёмка упаковки](deployment/FAMILY_RELEASE_ACCEPTANCE.md)
описывают подготовку пакета на компьютере разработчика и проверку встроенных инструментов.
Полную установку проверяем отдельно по инструкции оператора.

Технические правила приложения: [TECHNICAL_DESIGN.md](design/TECHNICAL_DESIGN.md),
[настройки](design/INSTANCE_SETTINGS.md), [категории](design/CATEGORY_MANAGEMENT.md),
[история](design/HISTORY_BROWSING.md). Код имеет приоритет при расхождении с документацией.
